# tools/warp — 3D 왜곡 강건성 측정 하네스

R2 정합 계층이 「어디까지 되는가」를 재는 스크립트들. **전부 읽기 전용 측정**이고
`src/` 를 고치지 않는다. 산출물은 `test/output/` 아래로 나가며 그쪽은 gitignore 다.

> ⚠ 이 폴더가 왜 생겼나: 처음엔 이 스크립트들을 `test/output/` 안에 뒀는데 그 경로가
> gitignore 라 **git 으로 공유가 안 됐다.** 다른 기계에서 돌리려 했더니 「기준선 자산이
> 트리에 없다」로 막혔고 공유 드라이브로 손 배치해야 했다. 생성기는 소스이고 산출물이
> 아니다 — 그래서 추적되는 곳으로 옮겼다.

전부 **repo 루트(`TLcube/`)에서** 실행한다: `node tools/warp/<이름>.mjs`

## 사다리 (재료 생성 + 현행 한계 측정)

| 스크립트 | 재는 것 |
|---|---|
| `ladder-perspective.mjs` | 원근 축. **설계 상한 0.5** 안에서 한계선을 집계하고 그 위 두 칸은 참고로 남긴다 |
| `ladder-axes.mjs` | yaw · pitch · roll · 3면/6면. 축마다 따로 훑는다 (곱집합 금지) |
| `probe-equiv.mjs` | 평행투영 동치 — `perspective 0` 이 기존 렌더와 같은가 |

**재료 규약 (실측으로 확정)**: `encodeY(payload, { cellSurfaceLayout: 'v0', tones: 3, eccLevel: 'M' })`.
`cellSurface: true` 나 `v1r2`·`v2r2` 는 정본 렌더로도 복호가 안 돼 재료로 못 쓴다.
두 사다리 모두 **기준선 게이트**가 있다 — 중립값이 안 읽히면 사다리를 만들지 않고 멈춘다.

## 대조군 (원인을 가르는 것)

| 스크립트 | 가르는 것 |
|---|---|
| `control-flat-tilt.mjs` | 「yaw/pitch 10° 실패」가 **기하**인가 **재료**인가. 같은 재료를 평면으로 렌더해 카메라 기울기를 준다 — 50° 까지 버티므로 기하가 원인이다 |
| `culling-demo.mjs` | 등 돌린 면을 걸러도 상이 바뀌는가 — 자세 405개 전부 0.000%. 화가 알고리즘이 이미 옳게 덮는다 |

## 포즈 (설계 판단 근거)

| 스크립트 | 재는 것 |
|---|---|
| `pose-measure.mjs` | **(a) 면별 호모그래피 vs (b) 큐브 포즈** 를 같은 입력에 물린다. 합격 축 = 셀 중심 예측 오차 < 0.33 셀피치 |
| `pose-diagnose.mjs` | 면별 투영 기하 — 어느 면이 언제 실오라기가 되나 |
| `visibility-envelope.mjs` | 3면이 유지되는 자세 범위 |
| `viewer-to-world.mjs` | **뷰어 파라미터 ↔ 관측자 위치.** `관측자 고도 = 35.264° − pitch` |
| `tolerance-band.mjs` | pitch 허용치를 넓히면 설 수 있는 구간이 얼마나 넓어지나 |
| `pose-fine-sweep.mjs` | **자세 허용치를 1° 눈금으로.** 10° 격자는 상한만 묶는다. 면별 조명 이득도 같이 잰다 |

## 지금까지의 실측

- 현행 디코더 한계: **원근 0.1** · **yaw −2°~+1° · pitch −1°~+2°** · roll 45° 이상 · 3면/6면 무관
- 두 축은 **독립이 아니다** — 원근 0.1 에서 pitch 여유가 0° 한 점으로 붕괴한다
- 평면 기울기는 **50°** 까지 버틴다 ⇒ 문제는 재료가 아니라 «세 면이 서로 다른 평면»
- 면별 조명 이득에는 강건하다 — 2.8배 비(1.0/0.6/0.36)까지 복호된다
- 목표선 **원근 0.5** — 상한이 아니라 요구를 성립시키는 **하한**이다 (여유 0)
