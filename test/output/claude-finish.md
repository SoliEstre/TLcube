## 1. rs211 소거(erasure) 복호 — 완결

### 1.1 무엇을 했나

`src/rs211.js` 에 소거 위치 목록을 받는 복호 경로를 추가했다. **기존 경로는 문자
그대로 무변경** — `options.erasures` 가 비면 예전 코드가 그대로 실행된다 (테스트로 고정).

| 추가 | 계약 |
|---|---|
| `rsDecode(received, nsym, { erasures })` | 배열 인덱스 목록. 한계가 `2v ≤ nsym` → **`2v + s ≤ nsym`** |
| `rsDecodeWithErasures(received, nsym, erasures, options)` | 호출부에서 «소거를 쓴다» 가 읽히는 별도 진입점 |
| `erasureCapacity(nsym)` = nsym | 소거만이면 패리티 수만큼 고친다 |
| `errorCapacityWithErasures(nsym, s)` = ⌊(nsym−s)/2⌋ | s > nsym 이면 −1 (복구 불가를 값으로) |

성공 결과에 `erasurePositions` · `erasureCount` · `correctedPositions` 가 붙고,
`errorPositions` 는 **소거가 아닌** 위치 미상 오류만 센다 (C_RS = 2u + e 회계용).

알고리즘: Γ(x) = ∏(1 − Z·x) 소거 위치자 → Forney 신드롬 `T = (S·Γ mod x^nsym)` 의
**계수 s..nsym−1** → BM → Ψ = Λ·Γ → Chien → Forney(Ψ, Ψ′).

> **표수 2 함정 (주석에 남겼다)**: reedsolo 계열 GF(2^m) 구현의
> `f[j] = f[j]·X ^ f[j+1]` 을 베끼면 안 된다. 소거 항 (X + X_k) 가 소멸하는 건
> 표수 2 에서만이다. 소수체 GF(211) 에서는 (X_k − X) 라야 소멸한다 — 여기서는
> Γ 곱셈으로 그 뺄셈을 자동으로 얻는다. 이 파일의 기존 주석이 경고하던 것과 같은 계열의 함정.

### 1.2.1 [r2 정정] 결론 사거리 축소 — 「정직성 충족」은 절벽 앞에서 멈춘 측정이었다

r1 은 «**ECC 한계의 정직성 요구 충족**» 이라고 닫았다. **그 문장은 취소한다.** r1 이 잰
rung 은 +1(안전)과 `s > nsym`(자명한 조기 반환 가드) 둘뿐이고, **사이에 있는 +2 rung 을
재지 않았다.** 하필 §2.1 이 이득으로 내세우는 운용점(«불법 심볼 **nsym 개**»)이 그 미측정
구간에 있다.

r2 에서 +2 rung 을 전수로 쟀다 (nsym ∈ {3,7,11,14,22,23,37}, 잔여 패리티 `nsym − s` 별
420/420/360/360/300/300 케이스, `claude-finish-rs-kat.mjs`):

| 잔여 패리티 `nsym − s` | 0 | 2 | 4 | 6 | 8 | 10 |
|---|---|---|---|---|---|---|
| 정직 실패 | **0** | 343 | 351 | 359 | 300 | 300 |
| **조용한 오정정** | **420 (100 %)** | 77 (18.3 %) | 9 (2.5 %) | 1 (0.3 %) | 0 | 0 |

**정정된 결론 — ECC 가 방어선인 구간은 `2v + s ≤ nsym + 1` 까지다.**

- **`s = nsym` 은 확률이 아니라 절벽이다.** 소거 nsym 개면 신드롬 nsym 개와 미지수
  nsym 개가 정확히 결정계라 해가 유일하고, 그 해는 정의상 모든 신드롬을 0 으로 만든다.
  4중 관문의 마지막인 «정정 후 신드롬 재검산» 이 **구성상 반드시 통과한다** — 미선언
  오류 1개면 100 % 조용히 오정정된다 (실측 420/420, 별도 표본 3500/3500). RS 고유
  한계이지 구현 결함이 아니다. 고칠 수 있는 종류가 아니라 **선언해야 하는 종류**다.
- **적대 검증이 권고한 «s ≤ nsym−2 구간에서 정직» 도 그대로는 쓰지 않았다** — 실측이
  그 표현을 지지하지 않는다. 잔여 2(= `s = nsym−2`)에서 조용한 오정정이 18.3 % 로
  실재한다. 정직성을 가르는 변수는 `s` 의 절대값이 아니라 **잔여 패리티 `nsym − s`** 다.
- **절벽 지점에서 상위층이 유일한 방어선이다.** ECC 가 아니라 페이로드 프레이밍
  (base-211 범위 · 길이 헤더 · UTF-8 유효성 · 0 패딩)이 막는다. 종단 실측: 소거 nsym 개
  \+ 미선언 오류 1개를 V3 M/H · V2 M · 최대(65 B)·짧은 페이로드에 걸쳐 **160/160 정직
  실패, RS 가 막은 건 0, 종단 오수용 0**. 막은 단계는 `base211` · `header` · `utf8`
  세 갈래가 **모두** 동원됐다.
- 이 사실은 주석이 아니라 **단언**으로 고정했다 (§6 참조): `test/rs211.test.js` 의 절벽
  rung 2건이 RS 층에서, `test/decode.test.js` 의 «상위층이 유일한 방어선» describe 2건이
  decode 층에서 양쪽을 못 박는다. 프레이밍 검사를 느슨하게 만드는 변경이 오면 후자가
  먼저 빨개진다.
- 남는 잔여 위험(코드 변경 대상 아님, 기록): `crsDistance` 는 점수·타이브레이크일 뿐
  절대 게이트가 없어(`bootstrap.js:1674, 1700`) **단독 후보라면 예산 전액을 쓴 복호도
  그대로 채택된다.** 최소 계약으로 «절벽 지점의 `crsDistance` 가 `nsym` 을 정직하게
  보고한다» 를 테스트로 고정해 상위 소비자가 읽을 수 있게 했다.

## 2. 프레임 밖 / 미표본 셀 = 소거 — 완결 (단위 층)

### 2.1 본문 셀

- `sampleCubeGrid` · `sampleHexGrid` 에 **옵트인** `collectUnsampled` 추가. 켜면 표본을
  못 만든 셀에서 즉시 실패하지 않고 `unsampled` 목록으로 모아 계속 간다. 끄면(기본)
  예전과 동일. 한 셀도 못 읽으면 여전히 실패한다.
- `validateGridHypotheses` 가 이 옵션을 켜고, 미표본 셀·불법 톤 triple 위치를
  scan-order 인덱스로 모아 `decodeCells(digits, format, { erasureCells })` 로 넘긴다.
- `decodeCells(cellDigits, format, options)` 신설 3번째 인자:
  `erasureCells`(scan-order 셀 인덱스, ⌊i/3⌋ 심볼로 환산) · `erasureSymbols` ·
  `erasureMode`. filler 구간 인덱스는 코드워드가 아니므로 소거로 세지 않는다.
- `crsDistance` 가 `2u` → **`2u + e`** 로 정정됐다 (소거는 패리티 1칸).

`RS211_ERASURE_MODE` 값이 `'error-only-fallback'` → **`'erasure'`** 로 바뀌고,
옵트아웃용 `RS211_ERASURE_MODE_LEGACY` 를 새로 export 한다. 기존 decode 테스트는
**약화하지 않고 강화**했다 — 같은 입력에서 `corrected 1 / crsDistance 2` (오류 취급)
가 `corrected 0 / crsDistance 1` (소거 취급) 로 바뀌는 것을 고정하고, legacy 모드
테스트를 따로 세워 옛 동작도 계속 검증한다.

새 decode 테스트 (`test/decode.test.js`, r1 +8 · **r2 +2 = 총 +10**):

| 확인 | 수치 |
|---|---|
| 불법 심볼 **nsym 개** — 소거는 성공 / legacy 는 실패 | V3 M: nsym 23 vs t 11 → 소거가 정확히 2배 도달 |
| 프레임 밖 셀 nsym 심볼분 (3·nsym 셀) | 위치 알면 복구, 모르면 실패 |
| 소거 nsym+1 | `ok:false` (억지 복구 금지) — **[r2] 이름 축소**: 이 테스트가 치는 것은 «개수 > nsym» 조기 반환 가드 하나뿐이다 |
| filler 인덱스 | 소거로 세지 않음, `crsDistance 0` |
| 범위 밖 인덱스 | `erasure:` 단계 실패로 보고 |
| 결정성 | 2회 deepEqual |
| **[r2 신규] 절벽에서 상위층이 유일한 방어선** | 160 케이스 종단 — 오수용 0 · RS 가 막은 건 0 · `base211`/`header`/`utf8` 3층 전부 동원 |
| **[r2 신규] 절벽 지점 `crsDistance`** | `= nsym` (예산 전액) · `corrected 0` 을 정직하게 보고 |

**[r2 정정] 위 «불법 심볼 nsym 개» 행이 §1.2.1 의 절벽 지점이다** — 이 운용점에서
RS 의 검출 마진은 0 이다. 이득(정확히 2배 도달)은 사실이지만, 그 도달점에서
«틀렸다» 고 말하는 능력은 ECC 가 아니라 페이로드 프레이밍이 댄다.

### 2.2 포맷 15셀 3중 복제

`format-proposals.js` 가 digit `null` 을 **소거** 로 받는다 (0..5 정수와 구분).

- 위치별 다수결에서 소거된 복제는 **표에서 빠지고**, 정족수를 남은 관측 기준으로 다시 센다
  (`'2/2'` · `'1/1'` 같은 상태 라벨 + `survivorDecided` · `erasedPositions` 진단).
- **소거 digit 이 하나라도 있는 복제는 개별 proposal 로도 만들지 않는다** — 빈자리를
  0 으로 메운 5-digit 은 관측이 아니라 날조다.
- `bootstrap.js` 의 `readFormatForHypothesis` 가 표본 실패·판독 불가 셀에서 즉시 죽지
  않고 `null` 을 넣는다. 15셀 **전부** 소거일 때만 예전처럼 실패.

새 테스트 (`test/format-proposals.test.js`, r1 +5 · **r2 +5 = 총 +10**) 중 핵심 한 건은 «0 위장이 왜 나쁜가» 를
직접 대조한다: 같은 자리를 0 으로 «관측한 척» 한 복제 2개가 멀쩡한 1개를 2/3 으로
이겨 **오답 다수결**을 만든다. 같은 상황을 `null` 소거로 표시하면 살아 있는 관측이
이기고 CRC 도 통과한다.

#### [r2 추가] 이 변경이 새로 연 수용 표면에 이름을 붙인다 — 「**생존자 키메라**」

r1 은 이 표면을 기록하지 않았다. 적대 검증이 «이름 없는 신규 수용 표면» 으로 집어냈고,
r2 에서 이름과 방어선을 정본화했다 (`src/format-proposals.js` 주석 + 테스트 5건).

**무엇인가**: 자리마다 살아남은 복제가 다를 수 있다. 위치 0 은 복제 0·1 이, 위치 4 는
복제 2 만 살아 있는 식이다. 그러면 `majorityDigits` 는 **어느 한 복제에서도 통째로
관측된 적이 없는 5-digit 조합**이 된다 — 자리별 관측을 이어 붙인 키메라다. 변경 전에는
`readFormatForHypothesis` 가 첫 미표본 셀에서 죽어 도달할 수조차 없었다.
**퇴행이 아니라 신규 표면이다.** 같은 파일이 «빈자리를 0 으로 메운 복제» 를 날조라며
개별 proposal 에서 빼는데 키메라는 만든다 — 그 비대칭을 정당화하는 것은 아래 넷뿐이다.

| 방어선 | 내용 | 단언 |
|---|---|---|
| ① 자리별 실관측 | 어떤 digit 도 지어내지 않는다. 각 자리 값은 그 자리에서 실제로 읽힌 값 중 유일 최다일 때만 채택 | 5자리 전부 실관측 집합 안 |
| ② 동수면 포기 | 관측이 갈리면(1:1) 임의 선택하지 않고 다수결 자체를 세우지 않는다 | `majority === 0` |
| ③ **CRC-6 가 유일한 관문** | 5-digit 공간 7776 중 유효 64 (약 0.82 %). 소비자(`bootstrap.js:2465·2830·2876`)가 `crcOk` 를 하드 게이트로 쓴다 | CRC 틀린 키메라 → `crcOk:false`, 통과 후보 0 |
| ④ 관측 0 인 자리 | 한 자리라도 생존 관측이 0 이면 키메라를 만들지 않는다 | `proposals === []` |

**남는 위험(정직하게)**: 키메라에는 «몇 복제가 지지했는가» 같은 추가 방어가 없다.
CRC-6 다음은 곧장 본문 RS 다. 잘림·가림·skew 전 축(ok 행 1331)에서 오수용 실측 0 이지만
그건 «0 을 쟀다» 이지 «0 임을 증명했다» 가 아니다. 정족수 완화·`crcOk:false` 후보 승격은
이 표면을 넓히므로 ①②를 다시 세워야 한다.

### 2.3 레퍼런스 셀 보정도 부분 관측 허용

`cube-detect.js` 의 `referenceSampleMap` 이 잘린 레퍼런스 셀 하나에 전체 보정을
죽이지 않는다 — 잘린 셀은 지도에서 빠지고 남은 셀로 보정을 세운다.
**게이트는 완화하지 않았다**: `agreementRate` 분모는 여전히 전체 레퍼런스 수라
못 읽은 셀은 «불일치» 로 계산된다. 재료가 정족수(0.6) 미만이거나 톤 pool 이 비면
`hardChecks.all = false` 인 «정직한 실패» 보정본을 돌려준다.

## 3. 부분 앵커 포즈 완성 — **미구현.** 측정이 전제를 뒤집었다

브리프의 전제는 «코너 앵커 4개 중 3개 이상이 정합하면 나머지를 외삽하라, 현행은
특정 앵커(SE) 의존이 강해 그 코너가 잘리면 죽는다» 였다. 4 의 하네스로 재보니:

**① SE 의존이 이 하네스에서는 보이지 않는다.** 잘림 방향별 실패 수 (after, 144프레임):

| 방향 | 5% | 10% | 15% | 20% |
|---|---|---|---|---|
| corner-**se** | 12 | 12 | 12 | 12 |
| corner-**nw** | 12 | 12 | 12 | 12 |
| edge-right | 12 | 12 | 12 | 12 |

전부 12/12 실패 — 방향 비대칭 0. SE 코너가 특별히 취약하다는 신호가 없다.

**② 죽는 곳이 앵커가 아니다.** 실패를 결정하는 단계를 탐침
(`test/output/lanes/claude-finish-clip-probe.mjs`) 으로 찍었다:

> **[r2 정정] r1 의 이 전사(轉寫)는 두 실행을 합성한 것이었다.** 적대 검증이 «재현 안 되는
> 증거 블록» 으로 잡았고, 재실행으로 확인했다 — `symbol-clipped` 계열 전사는 `v2r2@21` 이
> 아니라 **`v0@13`** 의 것이다. 결론(«잘린 프레임은 RS 이전, 기하 가설 생성 단계에서 죽는다»)은
> 두 경우 다 성립해 살아남지만, 라벨이 틀린 인용은 그대로는 재현되지 않는다. 두 전사를 분리한다.

```
[재현] node claude-finish-clip-probe.mjs "v2r2@21" edge-right 0.05
v2r2@21 edge-right 5%  →  hypothesisCount 198 · formatProposalCount 0 · bodyValidCount 0
                          → 남은 가설은 전부 qr-center-hex-* (다른 패밀리)
                          → frontend:no-format-candidate 로 반환
                             (포맷 proposal 이 0 이라 후보 자체가 없다)

[재현] node claude-finish-clip-probe.mjs "v0@13" edge-right 0.05
v0@13   edge-right 5%  →  cube hypothesisCount 0 · qr hypothesisCount 24
                          cube: no-positive-hex-y-junction
                          → bootstrap.js «qr-only-no-valid-format» 이
                             frontend:symbol-clipped 로 **분류**해 반환
```

`frontend:symbol-clipped` 는 표본 실패가 아니라 **분류 라벨**이다. 그 아래의 실제
사건은 «**cube/cell-surface 기하 가설이 하나도 만들어지지 않았다**» 다. 즉 잘린
프레임은 중앙 Y-junction / 셀표면 블록 로케이터 단계에서 이미 끝난다 — 앵커 4개 중
3개를 세는 지점에 **도달조차 못 한다**.

그래서 «3개 이상 정합 → 외삽» 을 지금 넣으면 **한 프레임도 지나가지 않는 코드**가 된다.
넣지 않았다. 들어가야 할 자리와 조건을 대신 남긴다:

- **자리**: `cube-detect.js` 의 Y-junction 후보 생성 / `cellsurface-block-detect.js` 의
  블록 로케이터 — 즉 `enumerateGridHypotheses` 가 후보를 만드는 지점. 그 위(수용 게이트
  0.78/0.035)도 그 아래(RS)도 아니다.
- **선행 조건**: 로케이터가 «부분 실루엣»(육각형의 3/4 이하만 보이는 상태)에서 후보를
  내놓아야 한다. 현행은 닫힌 실루엣·완전한 Y-junction 을 요구한다.
- **잔차 상한**: 외삽 코너의 재투영 잔차는 완성 전 3점으로 세운 H 의 잔차 대비
  상대값으로 재야 한다 (절대 픽셀은 cell_px 에 의존). 게이트 0.78/0.035 는 완성된
  기하에도 **그대로** 적용 — 완화 금지 조항 준수.
- **오수용 증거**: 이번 측정에서 after 오수용 0 · 교차 레이아웃 선택 0 · 퇴행 0
  (§4.3) 이 현재 기준선이다. 완성 로직이 들어가면 이 세 수치가 0 을 유지하는지가
  1차 방어선이다.

### 7.3 브리프에서 벗어난 판단 1건 (보고)

브리프는 §1.2 결론을 «**s ≤ nsym−2 구간에서 정직**» 으로 좁히라고 지시했다.
**그 표현은 쓰지 않았다** — 내 재측정이 지지하지 않기 때문이다. `s = nsym−2`
(잔여 패리티 2) 에서 +2 rung 의 조용한 오정정이 **18.3 %** 로 실재한다 (420 중 77).
적대 검증 렌즈1 자신의 표에도 같은 값이 있다 (nsym 23 · s 21 · v 2 → 조용한 오정정
93/500 = 18.6 %) — 권고 문구가 그 데이터보다 느슨했던 것으로 보인다.

정직성을 가르는 변수는 `s` 의 절대값이 아니라 **잔여 패리티 `nsym − s`** 이고,
`s = nsym` 만이 확률이 아닌 **구성상 절벽**이다. 그래서 결론을 «ECC 가 방어선인 구간은
`2v + s ≤ nsym + 1`» 로 쓰고, 잔여 패리티별 실측 표를 같이 실었다. 지시의 **의도**
(사거리 축소 + 절벽 명시 + 상위층 방어선 고정)는 전부 이행했다.
