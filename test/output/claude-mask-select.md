## 1. 마스크 후보 3종 — 3관문 실측

### 1.1 후보 유도 — 새 매직넘버 없음

`src/mask.js` 헤더의 선정 절차(①카이제곱 균등성 · ②이웃 상관 · ③축 자기상관)는 그대로 두고,
**이미 선정된 hash 공식 하나에서만** 후보를 파생시켰다. 아발란치 직전 단계에 상수를 XOR 한다:

```
hashSeeded(q, r, seed):
  h = (q · 0x9e3779b1) ^ (r · 0x85ebca77)
  h ^= seed                       ← 개정이 더한 유일한 자유도
  h |= 0 ; h ^= h >>> 15 ; h = imul(h, 0xc2b2ae35) ; h ^= h >>> 13 ; h |= 0
  return h mod 6
```

| index | seed | 출처 | 성질 |
|---|---|---|---|
| 0 | `0x00000000` | — (XOR 항등) | **현행 hash 와 연산 하나까지 동일** → 구 와이어 보존 |
| 1 | `0x9e3779b1` | 이 공식의 q 계수 (황금비) | 새 상수 아님 |
| 2 | `0x85ebca77` | 이 공식의 r 계수 (murmur3 fmix32) | 새 상수 아님 |

기각된 affine / quadratic 은 재사용하지 않았다 (`CANDIDATES` 에 대조군으로 그대로 남아 있고
`test/mask.test.js` 의 «affine 은 ③에서 FAIL» 단언도 그대로다).

seed 를 **좌표에 곱하지 않고 상수로 XOR** 하는 이유: 좌표 평행이동이면 세 후보가 같은 필드의
사본이 되어 mimic 산포가 거의 안 생긴다. XOR 은 아발란치를 통과하며 필드를 흩는다 — §1.3 이 실측.

## 2. 포맷 v2 (6-digit) — 설계 · KAT · 레거시 공존

### 2.1 비트 배치 (운영자 확정 옵션 A)

```
payload  9 bit = 버전 4 | ECC 2 | 마스크 2 | 예약 1     (MSB-first)
codeword 15 bit = payload 9 | CRC 6
digit    6 (base-6, MSD-first)  ·  포맷 셀 = 3복제 × 6 = 18
```

- 6^5 = 7776 < 2^15 = 32768 → **5 digit 으로는 못 넣는다.** 6^6 = 46656 ≥ 2^15 → 6 digit.
- CRC 다항식·계산 규약 **v1 그대로**: `CRC_POLY = 0x07`, 비반사·MSB-first·init 0·xorout 0.
  폭만 6bit → 9bit 메시지로 늘었다 (`crc6v2`).
- 고정 출력 마스크도 **같은 유도 규칙**(CRC_POLY 를 코드워드 폭만큼 반복) 확장:
  `(0x07<<12) | (0x07<<6) | 0x07 = 29127` → `MASK_DIGITS_V2 = [3,4,2,5,0,3]`. 새 상수 없음.
- 예약값 처리: ECC 3 · 마스크 index 3 · 예약 bit 1 은 **디코더가 CRC 보다 먼저 거부**한다
  (미래 개정본을 조용히 오독하지 않는다).

### 2.2 CRC 재측정 — 다항식을 바꿀 근거가 없다

같은 5 후보를 9bit / 15bit / 6digit 에서 전수 재측정 (512 코드워드 · 130,816 쌍).

| 이름 | poly | digit 최소거리 | bit 최소거리 |
|---|---|---|---|
| CRC-6/ITU | 0x03 | 1 | 3 |
| CRC-6/CDMA2000-A | 0x27 | 1 | 3 |
| **CRC-6/CDMA2000-B** | **0x07** | 1 | **4** |
| CRC-6/DARC | 0x19 | 1 | 4 |
| CRC-6/GSM | 0x2F | 1 | 4 |

1순위(digit 최소거리)가 **전 후보 동률 1** 로 무너진다 — 15bit 를 6digit 에 넣으면
코드워드가 digit 공간에서 촘촘해져 «한 digit 만 다른 유효 코드워드 쌍» 이 생긴다
(v1 은 12bit / 5digit 에서 2였다). 2순위(bit 최소거리)에서 {0x07, 0x19, 0x2F} 3파전 동률 4.
**재선정 근거가 없으므로 0x07 유지** — 브리프 지시와 측정이 같은 답을 낸다.

**대가의 실측** (유효 페이로드 144개 = 예약 0 · 마스크 ≠ 3 · ECC ≠ 3, 단일 복제 기준):

| 오염 | 경우의 수 | 미검출 | 검출율 | v1(5digit) 대비 |
|---|---|---|---|---|
| 1-digit | 4,320 | 2 | **99.9537 %** | 100 % → 99.95 % (**하락**) |
| 2-digit | 54,000 | 196 | **99.6370 %** | 99.1125 % → 99.64 % (상승) |

**3중 복제 다수결은 «한 복제의 1-digit 오염» 을 전수 복구한다** — 144 페이로드 × 6자리 ×
5값 = 4,320 케이스 전수를 테스트가 단언한다. 즉 단독 복제 검출율 하락은 다수결이 덮는다.

### 2.4 레거시 공존

- v1 경로(`encode` / `decode` / `toDigits5` / `MASK_DIGITS` …)는 **한 줄도 안 바뀌었다.**
  KAT 재확인: `encode({0,0}) = [0,2,0,3,5]`, `MASK_DIGITS = [0,2,0,3,5]`.
- 두 경로는 자릿수로 강제 분리된다 — v1 함수에 6digit 을 넣거나 v2 함수에 5digit 을
  넣으면 `TypeError`. **조용히 자르지 않는다.**
- 포맷 v1 을 쓰는 곳: Type O · Type A · 레거시 Type Y · CS-v1(61셀) · **초안·소각 와이어
  (`cellSurfaceLayouts.js` v1r2d · v2)**. 브리프대로 무수정.
- 구 디코더가 v2 프레임을 만나면: 포맷 셀 **좌표 자체**가 달라진다(§3.1 표). 구 디코더는
  자기 autoplace(복제 길이 5)로 15 좌표를 계산하는데 그 자리는 v2 프레임에서 대부분
  **데이터 셀**이다 → 마스킹된 임의 digit → CRC 불일치. `enumerateFormatProposals` 가
  버전 인덱스까지 걸러 유효 코드워드는 7776 중 6개(0.077 % / proposal)뿐이다.
  ⚠ **완전한 «오독 0» 은 아니다** — 참고로 «같은 셀을 읽고 앞 15 digit 만 5×3 으로 자르는»
  가상 구현을 모사하면 144 유효 페이로드 중 **4개(2.8 %)** 가 v1 CRC 를 통과한다
  (`lanes/formatv2-kat.mjs` `legacyReader`). 실제 구 디코더는 좌표가 달라 이 경로를 타지
  않지만, «깨끗한 거부» 는 **확률적 거부**로 읽는 것이 정확하다.
  ⚠ **r2 정정** — 이 2.8 % 는 **단일값이 아니라 절단 규약에 의존하는 구간**이다. 적대
  검증 재측정: 「앞 15 digit 을 5×3 으로」 규약에서 4/144 = 2.78 %, 「복제별 앞 5」에서
  **0.69 %**, 「뒤 15」에서 **6.25 %**. 위험 상한을 말하는 수치이므로 **0.69 \~ 6.25 %**
  로 적는 것이 정확하다. 통과 4건은 전부 버전 인덱스를 오독한다(0→6 · 3→11 · 6→7 ·
  12→3) — 무해한 accept 가 아니라 진짜 오독이다.
  그리고 **반대 방향**(구 프레임 → 신 디코더)은 이 라운드에서 «단절» 이 아니게 됐다 — §8.1.

### 3.3 부수 발견 — v0X@21 ECC-M 이 «인코딩 불가» 조합에 떨어졌다 (수정함)

`capacity.maxBytesForSymbols` 는 211^S 를 통째로 보고 `floor(S·log2 211 / 8)` 을 낸다.
그런데 실제 인코더(`base211.bytesToSymbols`)는 **27 B ↔ 28심볼 청크**로 담으므로 꼬리
청크에서 손실이 나, S = 1..400 중 **64개** 값에서 그 선언이 1 B 과대다. 그런 조합은
`decode.finishProfile` 이 «이 포맷은 현행 인코더가 생성할 수 없다» 로 이미 거부하고
있었다 — **선언이 틀린 것이지 게이트가 느슨한 것이 아니다.**

포맷 v2 로 v0X@21 의 S 가 116 → 115 가 되면서 ECC-M 의 dataSymbols 가 하필 그 86 에
떨어졌다 (dataBytes 83 을 선언하는데 인코더는 87 심볼을 요구 → `RangeError`).
`cellSurfaceFinal.js` 에 청크 정합 값으로 **낮춰** 선언하는 `packableBytesForSymbols` 를
넣었다 — 절대 올리지 않으므로 게이트 완화가 아니고, 나머지 14개 (레이아웃 × 레벨)

(15조합 전부 `symbolCountForByteLength(dataBytes) === dataSymbols`)를 추가했다.

거리 분류는 정본 §0 그대로: d ≤ 1.0 진짜 · 1.0 < d ≤ 2.5 near · d > 2.5 deep.

(코어 ≈ 10 × 클러스터라 기여를 1/10 로) · `W_true = 10` (진짜 1개 ≈ mimic 10개).

**모듈 분리 이유**: 생성기 단일 HTML 번들의 위상 정렬에서 `encodeY` 는 `sceneY`·`raster`

번들에 디코더 전체가 딸려 들어간다. 그래서 선택기를 인코더 **위**의 얇은 층으로 두고
`encodeY(..., { maskIndex })` 로 되먹인다. 결정성·계약은 그대로다.

## 7. §SPEC-초안 — 계약 변경 요약 (SPEC.md 는 이 레인 범위 밖)

통합자가 `SPEC.md` 에 반영할 항목. 표현은 초안이다.

### 7.1 §4.3 데이터 마스크 — 「고정 1종」 → 「후보 3종 + 선택」

- 마스크 공식은 `m_k(q,r) = mod6(mix((q·0x9e3779b1) ^ (r·0x85ebca77) ^ S_k))`,
  `S_0 = 0` · `S_1 = 0x9e3779b1` · `S_2 = 0x85ebca77`.
  `k = 0` 은 개정 전 고정 마스크와 **바이트 동일**하다.
- 선정 절차(3관문)는 불변. 후보 3종 전부 ①③ 통과 (§1.2 표를 SPEC 측정표에 승계).
- 인코더는 후보별 렌더-스캔 페널티 최소를 고른다(정본 §5.3 공식). ⚠ 현행 페널티가 왜곡
  강건성과 상관이 없다는 실측(§4.5)을 함께 싣거나, 선택 규범을 「잠정」으로 표시할 것.

### 7.2 §5.4 포맷 정보 — v1 / v2 두 세대

- **v1 (레거시, 유지)**: 12 bit = 버전 4 + ECC 2 + CRC 6 · 5 digit · 15셀.
- **v2 (신세대 셀 표면 전용)**: 15 bit = 버전 4 + ECC 2 + **마스크 2** + **예약 1** + CRC 6 ·
  6 digit · **18셀**. 필드 순서 MSB-first `version|ecc|mask|reserved`.
- CRC 다항식 · 규약 공유 (0x07, 비반사 MSB-first, init 0, xorout 0) — 폭만 9 bit 메시지.
- 고정 출력 마스크 v2 = `toDigits6((POLY<<12)|(POLY<<6)|POLY)` = `[3,4,2,5,0,3]`.
- 예약값: ECC 3 · 마스크 3 · 예약 bit 1 → 디코더는 **CRC 검증 전에 거부**.
- 세대 결정 규칙: **레이아웃이 정한다** (신세대 셀 표면 = v2, 그 외 = v1). 와이어에
  세대 비트는 없다 — 디코더는 기하에서 n · 레이아웃을 먼저 확정하므로 순환이 없다.

### 7.3 §5.5 용량표 — 신세대 셀 표면 5행 갱신

> ⚠ **r2 정정** — 「§3.2 표 그대로」는 **폐기**한다. SPEC §5.5 로 승계할 정본은
> **§8.5 의 15조합 실측표**(레이아웃 × ECC × {nsym · errorCapacity · dataSymbols ·
> dataBytes · maxPayloadBytes})다. 손산술로 전파하지 말 것.

data −3 · S −1 은 전 레이아웃 참이지만 payload 는 조합마다 다르다(−1 B 11개 · 0 셋 ·
**+1 B 하나**). v0X@21 ECC-M 의 dataBytes 는 청크 정합 값(82 B)이다 — §3.3.

### 8.1 A — 레거시 판독 공존 (F3 해소)

#### 구조

CS 레이아웃 디코더가 **포맷 v2(18셀) 우선 → 포맷 CRC 후보 전멸 시 v1(15셀) 폴백**.
두 좌표 집합은 **같은 `autoplaceY.placeReservedCells` 를 세대 파라미터만 바꿔** 돌려
얻는다 — 손 좌표표를 새로 만들지 않았다(c0e7321 계약 유지).

- `cellSurfaceFinal.js` — `CELL_SURFACE_FINAL_FORMAT_WIRES = [2, 1]` (디코더 시도 순서).
  `cellSurfaceFinal(n, id, formatWire)` · `formatCellsCellSurfaceFinal` ·

- `decoder/bootstrap.js` — 포맷 읽기를 `readFormatWithCells(…, formatWire)` 로 분리하고,
  CS-final 가설에서만 두 세대를 순서대로 시도. **폴백 조건은 «CRC 전멸» 하나**다 —
  샘플링이 깨진 기하(`stage: 'format-sampling'`)는 세대를 바꿔도 같은 셀에서 다시 깨지므로

  같은 세대로 유도한다 — 안 그러면 v2 좌표로 v1 프레임을 읽는다.
- `decode.js` — `format.formatWire` (기본 2). **v1 워드에는 마스크 필드가 없으므로
  폴백 경로의 `maskIndex` 는 0 이 아니면 거부**한다(조용히 무시하지 않는다).
- 제약 준수: `rs211.js` · `cellsurface-block-detect.js` · `cube-detect.js` **diff 0**.

### 8.2 B — 선택기 기본 OFF (와이어는 유지)

**생성기·API 기본 = 마스크 0 고정.** 포맷 v2 와이어는 그대로 두고 index 0 을 기록한다 —
포맷 셀 18개·6 digit·마스크 2bit 필드는 살아 있고, 값만 0 이다.

근거(재현된 실측, §4.5): n=21 두 레이아웃 × 6 페이로드 × 3 마스크 = 12 프레임에서
«S-커브 0.6 · 감마 0.7 **둘 다** 통과» 를 세면

| | 오라클(최선 마스크) | 고정 mask 0 | **페널티 선택** |
|---|---|---|---|
| 두 왜곡 다 통과 | **10 / 12** | 8 / 12 | **6 / 12** |

선택기가 고정보다 **나쁘다**(순 −2). 마스크 축의 지렛대 자체는 크지만(오라클 10 vs 고정 8)
**고르는 자가 틀렸다** — §5.3 클러스터 도메인 페널티는 왜곡 강건성의 대리가 아니다.

- 페널티 선택기는 `src/maskSelectY.js` 의 **옵트인 API** (`selectMaskIndexY` ·
  `encodeYWithMaskSelection`)로만 돈다. `encodeY` 는 선택기를 import 하지 않는다.
- `maskSelectY` 를 **생성기 번들(MODULE_ORDER)에 넣지 않았다** — 넣으면 생성기 단일
  HTML 에 디코더 전체가 딸려 들어간다(993 KB → 스캐너급 1.4 MB).
- 회귀 4건 신설(`maskSelect.test.js`): 기본 = 명시 0 과 **셀 digit 바이트 동일** ·
  `encodeY.js` 소스에 선택기 의존 부재 · 번들 2종에 `maskSelectY` 문자열 부재 ·
  옵트인 결과가 «그 index 로 인코딩한 것» 과 동일.

maxPayloadBytes} 전수 단언 회귀**를 신설했다(현행 세대 + 레거시 세대 = 30조합).

## 9. 통합 라운드 (finish 소거 다수결과 합성) — 2026-08-16

같은 함수를 두 레인이 서로 모르고 고쳤다. **ours = finish 레인의 소거 인지 다수결**
(`claude-finish.md` §2.2), **theirs = mask 레인의 포맷 v2 6-digit + 레거시 폴백**
(§2 · §8.1). 3-way 적용이 남긴 충돌 헝크는 `src/decoder/bootstrap.js` 4개 ·
`src/format-proposals.js` 2개. **어느 쪽도 깎지 않고 의미로 합성**했다.

**합성의 한 줄** — 잘린 복제는 **세대와 무관하게** 소거로 빠져야 한다. 세대별로 소거
규칙이 갈리면 폴백 경로(v2 → v1)에서 한쪽만 구제되는 비대칭이 생기고, 그 비대칭은
「v2 는 죽고 v1 은 살아난」 프레임에서 곧장 **교차 오독**이 된다.

### 9.4 남는 위험 (정직하게)

- **소거 상태의 교차 오독은 「0 을 쟀다」이지 「0 임을 증명했다」가 아니다.** 잰 축은
  5 인스턴스 × 3 ECC × 3 마스크 × 소거 복제 3 이고, 소거 패턴은 **복제 단위**와
  **자리별 키메라** 두 종류다. 임의의 부분 소거 패턴 전수는 아니다.
- **키메라의 방어선은 여전히 CRC-6 하나**이고, 이제 그 표면이 **두 세대 × 폴백** 으로
  넓어졌다. v2 는 예약 3종 선거부가 표면을 0.31 % 로 좁히지만 v1 폴백에는 그 필터가
  없다(ECC 예약 하나뿐, 0.62 %). 폴백을 걷어낼 시점의 판단 근거에 이 항을 더한다(§8.7-4).
- **소거가 폴백의 발동 빈도를 올린다.** 전에는 표본이 깨지면 폴백이 아예 안 돌았는데,
  이제 「일부 소거 + CRC 전멸」에서 돈다. 위 스윕은 그 경로에서 오독 0 이지만,
  폴백 실행 횟수 자체가 늘었다는 사실은 별개로 기록해 둔다.
