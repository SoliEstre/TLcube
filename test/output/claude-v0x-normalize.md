## 3. CS 채점 층 재측정 — 191/195 → **195/195**

`test/output/lanes/claude-v0xnorm-ab.mjs` 가 정규화 **전 스냅샷**(HEAD 의 `src/` 사본)과
현재 트리를 **같은 프로세스·같은 자**로 나란히 잰다. 표본기는 테스트와 동일한 이진
표본기(median 0.08/0.82)다.

| 타깃 | agreement 전 → 후 | margin 전 → 후 | 오방향 수용 |
|---|---|---|---|
| v0@13 | 1.000000 → 1.000000 | 0.3111 → 0.3111 | false → false |
| v2r2@21 | 1.000000 → 1.000000 | 0.2342 → 0.2342 | false → false |
| v2r2@25 | 1.000000 → 1.000000 | 0.2342 → 0.2342 | false → false |
| v1r2@21 | 1.000000 → 1.000000 | 0.1500 → 0.1500 | false → false |
| **v0X@21** | **0.979487 → 1.000000** | **0.1282 → 0.1231** | false → false |

- **정방향 일치율이 완전해졌다.** v0X 는 「정방향에서도 구조적으로 100% 를 못 찍는
  유일한 레이아웃」이었는데 그 성질이 사라졌다. 테스트의 `191/195` 레이아웃 분기도
  같이 사라져 세 후보가 한 줄(`agreement === 1`)로 단언된다.
- **방향 margin 은 0.1282 → 0.1231 로 살짝 내려갔다** (−0.0051, 게이트 0.035 의
  **3.5×**). 정규화가 (14,20) 을 (2,1,1) → (2,2,2) 로 만들어 그 셀의 위상 판별력이
  0 이 됐기 때문이다. 이건 **정규화의 실비용**이며 게이트 완화가 아니다.

> ⚠ 정정 — 정규화 전 margin 을 `claude-v0x.md` §4.1 의 **0.1538** 로 읽으면 틀린다.
> 그 값은 «이상 mid = 밴드 중앙» 표본기의 값이고, 테스트·이 표가 쓰는 이진 표본기의
> 값은 **0.1282** 다 (같은 md 의 retire 부기가 이미 정정해 둔 수치). 전/후를 같은 자로
> 재려면 0.1282 → 0.1231 로 읽어야 한다.

### 3.1 블록별 기여 (정규화 후 실측)

| 부분집합 | 셀 | 단독 margin | 절제 시 Δmargin |
|---|---|---|---|
| NW | 16 | 0.1667 | −0.0142 |
| **SE** | 36 | **0.0000** | **+0.1528** |
| NE | 6 | 0.4444 | −0.0327 |
| SW | 6 | 0.4444 | −0.0327 |
| **(14,20)** | 1 | **0.0000** (전 0.6667) | **+0.0019** (전 −0.0080) |

(14,20) 의 부호가 **뒤집혔다** — 정규화 전에는 유일한 «단면 점» 이라 셀당 판별력이
레이아웃 최대(0.6667)였고 총계에 +0.0080 을 보탰다. 지금은 3면 동일이라 판별력 0 이고,
있으면 오히려 희석한다(빼면 +0.0019). 즉 **(14,20) 은 더 이상 면 위상 큐가 아니다** —
`claude-v0x.md` §4.2 의 결론(「CS 채점 층의 면 위상 큐」)은 정규화로 폐기된다.
남은 역할은 위치 표식(3면 동시 점화)뿐이다.

### 3.2 지켜볼 것 — 교차 후보 점수가 게이트 쪽으로 조금 다가섰다

v0X 는 **자기 프레임이 아닌 곳에서 얻는 점수**도 같이 올랐다:

| 프레임 | v0x 경쟁 agreement 전 → 후 | 게이트 0.78 까지 여유 |
|---|---|---|
| v2r2@21 | 0.7333 → **0.7487** | 0.0467 → **0.0313** |
| v1r2@21 | 0.6923 → **0.7077** | 0.0777 → 0.0723 |

수용은 여전히 0 (`accepted: false`)이고 `ambiguous` 도 false 다. 다만 v2r2@21 프레임에서
v0X 의 여유가 **0.0313 까지 줄었다** — 정규화가 v0X 를 「더 평범한(3면 동일이 많은)」
무늬로 만들면서 남의 프레임에도 조금 더 맞아 들어가기 때문이다. 3-way 교차 오수용
테스트가 이 축의 방벽이고, 그 테스트는 그대로 초록이다. **경보는 아니고 관측이다.**

동반자)이 불변이라는 결론은 유지되나, 내부 상태까지 불변으로 읽지 말 것.

### 4.1 자 검증 — 「불변」이 진짜 불변인가

「전부 불변」은 **자가 안 움직였을 때도** 나오는 결과다. 그래서 자부터 확인했다
(`test/output/lanes/claude-v0xnorm-ruler.mjs`):

```
v0X 960² 프레임 다른 픽셀 : 834 / 921600 (0.090%)
```

프레임은 실제로 다르고(4면이 다른 색으로 칠해진다), 패치 점도 2개 늘었다(§2.1).
그런데도 코어 검출·동반자·포즈가 한 자리도 안 움직인다.

**왜 안 움직이나 (추정 아님, 구조):** 정규화된 4면 중 로케이터 패치에 드는 것은
(0,3).L 과 (19,19).R **둘뿐**이고((14,20) 은 어느 블록에도 없어 패치가 아니다),
둘 다 16점·36점 패치 안의 **1점**이라 Pearson 상관에 유의미한 변화를 못 준다.
K5 코어 검출은 SE 암 2×2 코어(17..18)² 와 명 링에서 나오는데 그 자리는 정규화 대상이
아니었다. 브리프가 기대한 「(19,19)R 복원으로 SE 회문이 R 면까지 완전해짐」은
**기하 서명으로는 사실**이지만(§1.2) **검출 결과로는 이미 포화**였다 — R 면 코어는
정규화 전에도 잡히고 있었다(동반자 6\~7 쌍은 «전»에서도 같은 값).

### 4.2 (14,20) 3면 동일 점화

정규화로 (14,20) 은 세 면이 모두 밝다. 로케이터 기여는 여전히 **0** 이다 — 어느 블록
상자에도 안 들어가 `blockLimitsFor('v0x')` 에서 빠지고, 1점 패치는 `registerPatch` 의
Pearson 최소 6점을 못 채운다. 바뀐 것은 CS 채점 층의 부호뿐이다(§3.1).

## 6. 구 인쇄물 호환 — 게이트 위임을 수치로

정규화 전에 인쇄·배포된 v0X 프레임은 4면이 mid 로 칠해져 있고, 새 디코더는 그 자리를

> **여유 0.1995**. 「호환은 게이트에 위임한다」는 판단이 수치로 받쳐진다.
