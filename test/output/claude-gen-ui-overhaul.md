### ⚠ g060 부가 설명 — 운영자 초안 문장은 **사실이 아니어서 그대로 달지 않았다**

운영자 초안: «\* 안전영역 옵션을 삽입할 곳 여건에 맞춰 자동 선택해 줍니다.»

코드 확인 결과:

* `generatorState.quietMode` **에 쓰는 곳은 카드 클릭 핸들러 하나뿐**이다
  (`index.html`, `for (const card of els.quietModeCards.children) { … generatorState.quietMode = card.dataset.quiet; … }`).
  즉 **안전영역 «옵션» 이 자동으로 바뀌는 경로는 코드에 없다.**
* 실제로 존재하는 것은 그보다 좁은 동작이다 — `highContrastQuietColor()` 가
  ① 1순위로 셀 레벨과의 휘도 분리가 큰 쪽(흰/검정)을 고르고
  ② 두 분리가 거의 같을 때(`Math.abs(sepW - sepB) > 0.02` 가 거짓일 때)만
  `lastBackdropLuminance` — **배치 미리보기 사진의 평균 휘도** — 로 흰/검정을 가른다.
  이 값은 `syncBackdropLayer()` → `measureBackdrop()` 이 채운다.
  적용 범위는 `quietMode` 가 `auto`(배경이 투명일 때) 또는 `contrast` 인 경우뿐이다.

그래서 «옵션을 자동 선택한다» 는 주장 대신 **코드가 실제로 하는 만큼만** 적었다 (g935):

> \* 넣은 표면 이미지의 밝기는 아래 «안전영역» 의 자동·고대비 색(흰/검정) 판단에 반영돼요.
> 안전영역 옵션 자체가 바뀌지는 않아요.

운영자가 «초안 문장 그대로가 아니면 아예 빼라» 를 원하면 `#backdropQuietNote` 한 줄과
g935 세 언어를 지우면 된다. 반대로 **정말로 옵션을 자동 선택하게** 만들 수도 있다 —
그건 UI 층이 아니라 정책 추가라 별도 판단이 필요해 이번 범위에서 뺐다.

## 2. A-2 «?» 툴팁 시스템

신규 모듈 `src/help-popover.js` (런타임 의존성 0 · 순수 ESM). 문서에 팝오버는 **하나**
(`#helpPopover`)이고, 버튼은 `data-help="<i18n 키>"` 로 자기 본문만 가리킨다 —
섹션이 늘어도 배선은 초기화 루프 하나다.

동작 계약 (실브라우저로 전부 확인):

| 상황 | 동작 | 확인 |
|---|---|---|
| hover 가능 기기, 마우스 올림 | 임시 툴팁, X 없음 | `hidden:false · pinned:false · closeHidden:true` |
| 마우스 뗌 | 닫힘 | `hidden:true` |
| 클릭 | 고정 + 우상단 X | `pinned:true · closeHidden:false` |
| hover 불가 기기(터치) | 탭 = 바로 고정 | 375×812 에뮬레이션에서 `matchMedia('(hover: hover)')` false → hover 무시, 탭에서 pinned |
| ESC | 닫고 버튼으로 포커스 복귀 | `hidden:true · aria-expanded:false` |
| 바깥 클릭(pointerdown) | 닫힘 | `hidden:true` |
| 같은 «?» 재클릭 | 토글 닫힘 | — |
| 언어 전환 | 열린 채로 본문 다시 그림 | ko 6줄 → en 6줄 즉시 교체 확인 |

접근성: `<button type="button">` · `aria-expanded` 를 상태에 맞춰 유지 ·
열릴 때 `aria-describedby="helpPopover"` 부여, 닫히면 제거 · 팝오버 `role="tooltip"` +
닫힘 시 `hidden` (접근성 트리에서 빠짐) · `aria-label` 은 사전 경유(g931 «설명 보기» ·
g932 «설명 닫기»). 본문은 `textContent` 로만 그린다 — 사전 문자열이라도 innerHTML
경로를 열지 않는다.

### 뷰포트 보정에서 **실제 결함 하나를 잡았다**

`positionHelpPopover` 는 순수 함수라 단위 테스트가 가능하다. 실브라우저에서 확인하다
보니 창이 화면 **아래로 삐져나간** 좌표가 나왔다 (top 795 · 높이 206 · 뷰포트 812).

원인: «아래가 모자라면 위로 뒤집는다» 분기의 조건이 `above >= edge` **뿐**이었다.
앵커가 뷰포트 아래로 벗어나 있으면(고정 팝오버를 두고 스크롤한 경우) `above` 가 큰
양수가 되어 이 분기를 통과한 뒤 아래로 넘친다. 두 분기 모두 «완전히 들어가는가» 로
바꿨고 회귀 테스트를 박았다 (`앵커가 뷰포트 밖(아래)이어도 창은 화면 안에 남는다`).

**«?» 를 붙인 섹션 (8개 버튼 / 7개 본문)**

| 섹션 | 본문 키 | 이관한 것 |
|---|---|---|
| 해상도 (모듈 밀도 = 용량) | g900 | 카드 4개의 `title=` (g002–g005) |
| 안정성 ⇄ 용량 | g901 | 카드 4개의 `title=` (g006–g009) + 자체검증 뱃지 읽는 법 |
| 배경색 | g902 | 카드 3개의 `title=` (g010–g012) |

| 안전영역 | g904 | 카드 3개의 `title=` (g014–g016) + 타이브레이크 규칙 |
| TL스캐너 QR링크 포함 | g905 | 카드 2개의 `title=` (g017·g018) |

## 4. A-4 검출기 선택 통합

### 통합 방식과 그 이유

`#finderSection` (O/A 중앙 파인더)과 `#yLocatorSection` (Y 셀 표면 로케이터)은
**동시에 보이는 일이 없다** (타입으로 갈린다). 그래서 DOM 을 합치는 대신 **두 제목을
같은 «검출기 선택» 으로 맞췄다** — 사용자 쪽에서는 타입을 바꿔도 같은 이름의 한 섹션이
자리를 지킨다. DOM 합치기를 피한 이유: `#finderSection` 이 점수 패널·접힘 후보군을 함께
들고 있고(별도 태스크 소관), 구조를 흔들면 그쪽 계약이 같이 흔들린다.

정식 화면 노출 범위는 **현행 그대로**다 — `#yLocatorSection` 은 여전히
`isLabPath() && type === 'Y'` 에서만 열린다 (정식 번들에서 `hidden:true` 확인).
검출기 자체의 정식 승격은 하지 않았다.

> ⚠ **이 문단은 처음에 틀렸었다.** 섹션(DOM)의 노출 범위는 그대로였지만 **도움말
> 본문**이 두 섹션 공유라서 lab 전용 내용이 정식 화면으로 샜다. 아래 §4-b 참조.

### «자동» 항목 — 현재 의미의 정의

```js
function resolveAutoLocatorProfileY() {
  return LOCATOR_PROFILE_OFF;
}
```

* **의미**: «지금 설정에서 권장되는 검출기를 쓴다».
* **현재 값**: 정식 승격된 Y 검출기가 아직 없으므로(v0 · v0X · v0XQ · v1r2 · v2r2 전부 lab
  실험 항목, g518 이 그 사실을 문구로 말한다) 권장값은 결정적으로 **끔**이다 —
  끔만이 스펙이 보증하는 경로다. 그래서 지금의 «자동» 은 «끔» 과 **바이트 동일한 결과**를 낸다.
* **상태 저장 위치**: `generatorState` 에 넣지 않았다. `locatorProfileY` 의 옵션 집합은
  «와이어에 실리는 값» 이고 자동은 그 값을 고르는 **UI 정책**이다. 모듈 안 플래그
  `detectorAutoY` 만 둔다 → 인코딩·게이트 경로 무수정, `GENERATOR_STATE_SCHEMA` 무변경.
* 자동을 고르면 «끔» 카드는 켜지지 않는다 (배타 표시) — 둘 다 켜져 보이면 «뭐가 적용된 건가» 가 생긴다.
* 승격이 일어나면 **이 함수 하나만** 바꾸면 된다. 화면 문구(g906)도 «현재 자동은 끔과 같다» 를
  명시해서 코드와 문구가 어긋나지 않게 했다.

### 카드 아이콘 = 실제 파인더 기하의 미니 도면

큰 사각 = n×n 셀 캔버스, 채운 블록 = 로케이터 블록의 **위치·상대 크기**,
**파선 사각 = 중앙 QR 슬롯** (v0XQ 뿐 — 파인더도 데이터도 아닌 제3 역할이라 실선
블록과 다른 획으로 그린다). 출처는 정본 `src/cellSurfaceFinal.js`:

| 카드 | 아이콘 | 부제 (ko) | 로케이터 셀 |
|---|---|---|---|
| 자동 | 사각 + 순환 화살표 | 권장값 자동 | — |
| 끔 (기존) | 파선 사각 + 슬래시 | 검출기 없음 | 0 |
| 셀 표면 v0 (Y0) | 코너 4블록 (소) | 코너 4블록 | **30** (n=13) |
| 셀 표면 v0X (Y1) | QR형 겹사각 3 + 소형 1 | QR형 코너 | **65** (n=21) |
| 셀 표면 v0XQ · 중앙 QR (Y1) | 겹사각 3코너 + 중앙 파선 슬롯 | 3코너 + 중앙 QR | **42** + 슬롯 **81** (n=21) |
| 셀 표면 v1r2 (Y1) | 코너 4블록 (대) | 코너 4블록 확장 | **80** (n=21) |
| 셀 표면 v2r2 (Y1/Y2) | 원점 블록 A + 먼 꼭짓점 블록 B | 중앙 + 원거리 앵커 | **74** (n=21·25) |

v0XQ 행(카드 아이콘 · 부제 g947 · 파선 슬롯 규약)은 통합 레인에서 붙였다 — 대개편
레인의 산출물에는 이 카드가 **아이콘도 부제도 없이** 이름만 있었다 (§12 참조).

### ⚠ 정정 (2026-08-16, 적대 검증 ★ → fix 레인) — 이 절의 용량표는 **틀렸었다**

원래 여기 실려 있던 표는 세 후보의 maxPayload 를 전부 `94 / 79 / 63` 으로 적고
«n=21 세 후보는 담을 수 있는 양이 완전히 같다» 고 결론지었다. **측정 실수였다.**

```js
capacityForCellSurfaceFinal(n, level = 'M', tones = 2, id = undefined)
```

네 번째 인자 `id` 를 **생략하면** `finalLayoutIdForN(21)` → `'v2r2'` 로 해소된다. 세
후보를 «각각» 잰다고 부른 세 번의 호출이 전부 v2r2 를 잰 것이었다. 세 숫자가 완전히
같게 나온 것 자체가 «자를 잘못 댔다» 는 신호였는데, 그 결론이 g906 본문으로 **3언어
전부에 실려 출고**됐다. 신규 46개 테스트 중 이 숫자를 고정한 것은 0건이었다.

**id 를 넘겨 다시 잰 실측:**

| 레이아웃 | n | 로케이터 셀 | usedSymbols | maxPayload L / M / H (B) |
|---|---|---|---|---|
| v0 | 13 | 30 | — | 29 / 25 / 20 |
| v0X | 21 | **65** | **115** | **96 / 81 / 65** |
| v0XQ | 21 | **42** + 슬롯 **81** | **96** | **80 / 67 / 54** |
| v1r2 | 21 | **80** | **110** | **92 / 77 / 62** |
| v2r2 | 21 | **74** | **112** | **94 / 79 / 63** |
| v2r2 | 25 | 74 | — | 145 / 124 / 99 |

톤 수(2·3)는 용량을 바꾸지 않는다 — 네 후보 모두 2톤 = 3톤.

**v0XQ 행은 통합 레인(2026-08-17)에서 붙였다.** 이 대개편 레인은 v0XQ 가 존재하는
줄을 몰랐다 — 두 레인이 같은 날 갈라져 각자 main 을 봤기 때문이다. v0XQ 는 이 표의
규칙성을 하나 깬다: **점유 ≠ 파인더**다. 중앙 QR 슬롯 81셀이 파인더도 데이터도 아닌
제3 역할로 빠지므로, 파인더 셀만 보면 42 로 넷 중 가장 작은데 용량은 넷 중 가장
작다(L 80 B). «파인더 셀이 적다 → 용량이 크다» 라는 위 1번 논증이 v0XQ 에서 뒤집힌다.
그래서 g906 문구는 «점유 셀» 로 말하고, 이 행만 파인더 수와 슬롯 수를 **따로** 적는다.

**부제에 «높은 용량» 을 쓰지 않은 이유 (재서술).** 앞의 근거(«전부 같으니 갈릴 수가
없다»)는 무효다. 실제 근거는 이렇다:

1. **갈리기는 갈린다, 그런데 폭이 작다.** 점유 셀이 적을수록 데이터에 남는 심볼이
   많다 (65 → 115 · 74 → 112 · 80 → 110). 순서는 v0X > v2r2 > v1r2 로 단조다.
   그러나 L 기준 폭은 **96 − 92 = 4 B**(≈4%)뿐이다. 카드 부제는 한두 단어짜리
   라벨이라 «대용량» 이라고 붙이면 사용자는 «눈에 띄게 더 담긴다» 로 읽는다 — 4 B
   차이를 그렇게 부르면 과장이다.
2. **기본값이 최대값이 아니다.** n=21 기본은 v2r2(94 B)이고 최대는 v0X(96 B)다.
   «대용량» 라벨을 v0X 에 붙이면 «기본을 두고 이걸 골라야 하나» 를 유도하는데, 그
   선택을 정당화할 인식률 근거가 없다 (g518 이 «보장하지 않는다» 를 말하는 상태).
3. 인식률 쪽은 여전히 실사 근거가 없다.

그래서 부제는 **검증 가능한 구조 사실**로만 두고(«코너 4블록» 류), 숫자는 «?»(g906)
안에 후보별로 **따로** 적는다 — 사용자가 4 B 차이를 직접 보고 판단할 수 있게.

**재발 방지.** `test/generator-help-capacity.test.js` 신설 (6건):
`capacityForCellSurfaceFinal` 에 **id 를 넘겨** 12값(n=21 네 후보 × L/M/H)을 핀으로 박고,
사전 문구에서 숫자를 파싱해 그 핀과 대조한다. «id 를 생략하면 후보들이 하나로 뭉개진다»
는 사실 자체도 테스트로 남겼다 — 다음 사람이 같은 자리에서 미끄러지지 않도록.
v0XQ 행은 파인더 수(42)와 슬롯 수(81)를 **각각** 파싱해 대조한다. 합계 123 하나만
적으면 «파인더가 123셀» 로 읽히고, 그건 이 절이 고친 것과 같은 종류의 거짓말이다.

내부 명칭(v0 · v0X · v0XQ · v1r2 · v2r2)과 정본 파일명은 **lab 전용 g906 안에만** 있다.

### ⚠ 4-b. 정식 화면 노출 — 도움말 키를 쪼갰다 (적대 검증 ③)

원래 이 절은 «정식 화면 노출 범위는 현행 그대로» 라고 적었는데 **틀렸다.** 두 섹션의

## 5. A-5 섹션 마진 일관화

**옛 규칙의 문제**: `.section-heading:first-child { margin-top: 0 }` 때문에 래퍼 div 안의
첫 헤딩만 위 여백이 0 이 됐다 (`#toneNormalSection` · `#backdropSection` · `#finderSection` ·
`#yLocatorSection` · `#decorSection` · `#panelNormal` …). 화면에서 18px 과 0px 이 섞였고,
그 차이의 원인이 «그 섹션이 div 로 감싸져 있는가» 라는 **사용자가 알 수 없는 사정**이었다.

**새 단일 규칙**

```css
.section-heading, .section-title { margin: 18px 0 6px; }               /* 기존 유지 */
.section-heading-row { display:flex; align-items:center; gap:6px; margin: 18px 0 6px; }
.section-heading-row > .section-heading,
.section-heading-row > .section-title { margin: 0; }
/* 예외 — 패널 최상단(콘텐츠)만 0. 패널 padding 과 겹치므로. */
.panel > *:first-child > .section-heading:first-child,
.panel > .section-heading:first-child { margin-top: 0; }
```

**함정 하나**: `.section-heading` 은 대부분 `<label>` 이라 `label:first-child { margin-top: 0 }`
(specificity 0,1,1 > 0,1,0) 이 새 규칙을 다시 0 으로 되돌린다. 그래서 그 리셋을
`label:not(.section-heading):first-child` 로 좁혔다.

**실측 (라이브 DOM, 375px)** — 전 섹션 헤딩의 `margin-top`:

```
콘텐츠 0px · 타입 18 · 톤 18 · 스타일 18 · 해상도 18 · 안정성 18 · 스타일프리셋 18 ·
배경색 18 · TL 배치 미리보기 18 · 안전영역 18 · QR링크 18 · 검출기 선택 18 ·
Y타입 셀 편집기 18 · 장식 이미지 18
```

예외는 «콘텐츠» 하나뿐 (근거 = 패널 padding 16px 와 중복).
가로 오버플로 0 (`documentElement.scrollWidth == innerWidth` at 375, 1280).

### 3태 기준 — 기존 자체검증 신호에서 기계적으로 유도

판정 규칙은 **순수 함수** `selfCheckVerdict()` 로 `src/render-status.js` 에 있다
(단위 테스트 `test/self-check-verdict.test.js`). 게이트마다 «한계 대비 관측» 비율 h 를
만든다 — h ≤ 1 이 통과, h 가 1 에 가까울수록 아슬아슬하다:

| 게이트 | 적용 | 비율 h | 계약값 |
|---|---|---|---|
| Δ 게이트 | O/A · Y 3톤 | `DELTA_MIN_CONTRACT / minDelta(Y)` | **0.12** (`src/luminance.js`) |
| 잔차 게이트 | Y | `maxResidual / ε_fit` | **0.01** (`EPSILON_FIT`, `src/verifyY.js`) |
| θ 마진 | Y 2톤 | `1 − logMargin / idealLogMargin` | `idealLogMargin = ½·ln(y_hi/y_lo)` |

θ 마진 항의 근거: `thetaFromAnchors` 가 `θ_f = √(y_lo·y_hi)` 이므로 두 앵커는 로그
도메인에서 **정확히 ½·ln(y_hi/y_lo) 만큼** θ 에서 떨어져 있다. 관측 마진이 그 절반이면
h = 0.5. 2톤의 `ok` 게이트에는 마진 하한이 **아예 없어서**(ok = 불일치 0 + 소거 0 +
잔차 통과), 이 항이 없으면 «성공이지만 경계» 를 잴 자가 하나도 없다.

**판정 (경계 띠 폭 `SELFCHECK_TIGHT_RATIO = 0.8`)**

| 라벨 | 조건 | 수치로 말하면 |
|---|---|---|
| **사용가능** (g950) | `ok === true` 이고 `max(h) ≤ 0.8` | 게이트 여유 20% 이상. Δ 축이면 `minDelta ≥ 0.15` |
| **인식곤란** (g951) | `ok === true` 이지만 `max(h) > 0.8` | 게이트 여유 20% 미만. Δ 축이면 `0.12 ≤ minDelta < 0.15`, 잔차 축이면 `maxResidual > 0.008` |
| **사용불가** (g952) | `ok === false` | 복호 불일치 / 소거 / 잔차 초과 중 하나 |

0.8 은 이 프로젝트가 고른 띠 폭이다. **임의 라벨이 되지 않도록 여유 %를 뱃지 아래에
같이 적는다** (g953 «게이트 여유 {pct}% — {tight}% 미만이면 «인식곤란»»). 사용자가 숫자로 확인할 수 있다.

### ⚠ 정정 (적대 검증 nit 1) — 여유 %가 뱃지와 어긋날 수 있었다

`headroomPercent = Math.round((1 − ratio) × 100)` 이라 **h = 0.801\~0.805 구간**에서 화면이
«게이트 여유 **20%** — 20% 미만이면 «인식곤란»» 이라 써 놓고 뱃지는 «인식곤란» 을 띄웠다.
폭은 0.5pt 지만 한 줄 안에서 두 주장이 서로를 반증한다.

고친 방식 (`src/render-status.js`):

* **내림**으로 바꿨다. 다만 순수 `Math.floor` 는 못 쓴다 — 이진부동소수 때문에 «정확히
  19%» 인 입력(잔차 0.0081 / ε 0.01)이 `18.999999999999996` 으로 떨어져 18 이 된다.
  그래서 `floor(x + 1e-9)` 다.
* 그러고도 경계에서 어긋날 여지를 없애려고, 표시값을 **판정과 같은 쪽에 붙인다**
  (marginal 이면 `≤ tight−1`, usable 이면 `≥ tight`). «뱃지와 문구가 서로 다른 말을
  하지 않는다» 를 계산이 아니라 **불변식**으로 보장한다.
* 문턱 %도 사전에서 뺐다 — `selfCheckTightPercent(tight)` 가 띠 폭에서 유도하고
  `{tight}` 로 꽂는다. 띠 폭을 옮기는 날 문구만 옛 숫자로 남는 사고를 막는다.

테스트 4건 추가 (`test/self-check-verdict.test.js`): 경계 띠 케이스 표 · **전 구간 스윕**
(5001점에서 «뱃지 marginal ⟺ 표시 % < 문턱 %» 불변식) · 부동소수점 한 칸 깎임 방지 ·
문턱 % 유도. 기존 4개 핀(34 · 4 · 19 · 95)은 **그대로 통과**한다 — 약화가 아니다.

⚠ 이 라벨은 **«렌더가 자기 계약을 얼마나 여유 있게 지켰는가»** 다. 라이브 인식률
예측이 아니다 — 그 주장에는 실측 근거가 없다 (파인더 점수판 g492 와 같은 규율).
문구도 그렇게 읽히도록 «?» (g901) 에 «인쇄·촬영 조건이 아니라 렌더가 자기 계약을 지켰는가만 본다» 를 적었다.

> 고친 대로 **내림**이다 (40.5 → 40 · 50.8 → 50 · 33.5 → 33). 같은 절 안에서
> «내림이어야 한다» 를 논증해 놓고 그 아래 표는 반올림으로 채운 것이다 —
> 자기가 방금 고친 규칙을 자기 표에 적용 안 한 자리다.

## B-1. 미리보기 캔버스 중앙화·꽉 채움

### 원인 — 세 겹이었다 (실측 1440×900, 미리보기 열 폭 1017)

`drawScene` 이 캔버스에 **인라인 px 크기**(`scene.width × 26`)를 박고 있었다. 그 값은
미리보기 영역 크기와 아무 관계가 없다. 여기서 두 갈래로 갈렸다.

* **박은 값이 열보다 작으면** — 예: 타입 O + 안쪽 QR 은 870px < 975px. 캔버스는
  `#canvasWrap`(`width:100%`) 안에서 `display:block` 이라 **왼쪽에 붙었다.**
  실측 좌우 여백 **54 / 159** (O+안쪽), **55 / 160** (O+QR없음). 이게 «왼쪽 쏠림» 이다.
* **박은 값이 열보다 크면** — `max-width:100%` 와 `max-height:calc(100vh-180px)` 가
  **서로 다른 축을 따로** 잘라서 요소 박스의 종횡비가 그림과 달라졌다. `object-fit: contain`
  이 그 박스 **안에서** 다시 레터박스를 만들었다 (Y/좌상: 박스 975×720, 그림 671×720 →
  가로 304px 이 빈 상자).

셋째로 `#stage` 는 그리드 행에 늘어나는 아이템이라 높이가 **컨트롤 패널**(2017\~2492px)을
따라갔다. 코드는 720px 로 잘려 위아래로 **649\~886px 씩** 남았다.

### 고친 방식 — 표시 크기를 CSS 가 정한다 (내부 해상도 불변)

```js
// drawScene: canvas.width/height (내부 해상도) 는 그대로. style.width/height 는 안 박는다.
function applyPreviewFit() {                       // drawScene 직후 호출
  const aspect = c.width > 0 && c.height > 0 ? c.width / c.height : 1;
  els.canvasWrap.style.setProperty('--code-aspect', String(aspect));
}
```

```css
#canvasWrap {
  aspect-ratio: var(--code-aspect, 1);
  width: min(100%, calc(var(--fit-h, 60vh) * var(--code-aspect, 1)));
}
@media (min-width: 761px) {
  main > #stage { align-self: start; position: sticky; top: 12px;
                  height: max(420px, calc(100vh - 80px)); }
  #canvasWrap  { --fit-h: max(378px, calc(100vh - 122px)); }   /* 무대 − 패딩40 − 테두리2 */
}
@media (max-width: 760px) { #stage { min-height: 240px; } #canvasWrap { --fit-h: calc(100vh - 220px); } }
```

폭이 정해지면 `aspect-ratio` 가 높이를 만든다 → **종횡비가 깨질 수 없다.** 두 축 중 하나는
항상 100% 를 채운다 = 왜곡 없는 최대치 = contain. 두 캔버스는 `position:absolute; inset:0`
으로 그 상자를 정확히 덮으므로 **요소 박스 == 그려진 그림**이 된다.

**종횡비는 `scene` 단위가 아니라 `canvas.width/height`(= drawScene 이 `Math.round` 한 뒤
값)에서 뽑는다.** 반올림 전 값을 쓰면 상자와 그림이 1px 어긋난다.

**sticky 는 장식이 아니라 필수다.** 무대를 뷰포트 한 판(820px)으로 줄이면, 그러지 않을 경우
2400px 짜리 패널을 스크롤하는 순간 미리보기가 화면에서 사라진다. 실측: `scrollY=900` 에서
무대 top 12 / bottom 792, 코드 보임 (뷰포트 860).

**무대 높이와 `--fit-h` 는 «패딩 40 + 테두리 2» 만큼 차이나야 한다** — 한쪽만 고치면 레터박스가
돌아온다. 이 산술을 테스트가 CSS 에서 파싱해 고정한다 (사람이 두 숫자를 같이 고칠 거라고
믿지 않는다).

### 부수적으로 잡힌 실제 결함 — 배경 드래그가 31% 덜 따라왔다

배치 미리보기의 팬/줌은 `ratio() = canvas.width / rect.width` 로 CSS px → 캔버스 px 를
환산한다. `rect` 는 **요소 박스**인데 레터박스가 있으면 그건 그림보다 크다.
Y/좌상에서 박스 975 · 그림 671 → 환산이 `1986/975 = 2.037`, 참값은 `1986/671 = 2.960`.
즉 커서를 100px 끌면 이미지는 **68.8px 만** 움직였다 (31.2% 부족 — 위 표의 실측 박스
수치에서 유도). 휠 줌의 앵커(`e.clientX - rect.left`)도 같은 이유로 어긋나 있었다.

박스 == 그림이 된 지금 실측: 100 CSS px 드래그 → 배경이 **274 캔버스 px** 이동,
기댓값 `100 × 2.740 = 274`, **오차 0.01%**.

## B-2. 스타일 섹션 버튼 바

### 프리셋 바 — «해당 프리셋 색의 진한 셰이드»

옛 바는 `preset.background` 를 그렸다. 그런데 세 프리셋의 배경은 전부 near-black 이다 —
slate `rgb(14,16,24)` · ember `rgb(18,11,7)` · mono `rgb(16,16,16)`. **세 카드의 바가 사실상
같은 검정**이라 프리셋을 구분해 주는 일을 전혀 못 하고 있었다.

```js
const DEEP_SHADE_K = 0.62;
function presetDeepShade(palette) {        // levels[1] = 그 프리셋의 색상을 가장 강하게 든 색
  const c = palette.levels[1];
  return { r: Math.round(c.r * K), g: Math.round(c.g * K), b: Math.round(c.b * K) };
}
```

sRGB 세 성분에 같은 계수를 곱하면 **색상·채도비는 유지되고 명도만 내려간다** — 정의 그대로
«그 프리셋 색의 진한 셰이드». 실측 결과:

| 프리셋 | 옛 바 (background) | **새 바 (진한 셰이드)** |
|---|---|---|
| slate | `rgb(14,16,24)` | **`rgb(68,84,118)`** |
| ember | `rgb(18,11,7)` | **`rgb(124,74,25)`** |
| mono | `rgb(16,16,16)` | **`rgb(93,93,93)`** |

테스트가 ① 셋의 채널 합 차이 ≥ 40 ② 각 셰이드가 원 레벨보다 어두움 ③ **옛 배경 셋의 차이는
40 미만** (= 이 회귀의 전제) 을 `src/luminance.js` 의 실제 PRESETS 로 계산해 고정한다.

### 커스텀 버튼 — hue 바를 버튼 안으로

카드 안의 고정색 바(`#customBg`)를 **없애고 그 자리에 `#hueBar` 슬라이더를 넣었다**
(`.hue-bar.in-card` — 트랙 8px + margin-top 2px 로 `.swatch-bg` 가 앉던 자리와 정확히 같다).
카드 밖 `#hueRow` 에는 수치 문구(g431)만 남고, 그건 커스텀일 때만 뜬다.

**바는 커스텀이 선택돼 있지 않아도 항상 보인다** — 바를 움직이는 것 자체가 커스텀 선택
경로이기 때문이다. 숨기면 그 진입로가 사라진다.

| 조작 | 결과 | 실측 |
|---|---|---|
| 바 드래그 / 터치 / 방향키 | 값 변경 + **커스텀 자동 선택** | slate → `input` 1회 → active `custom`, 고급 select 도 `custom` 로 동기화 |
| 바에 포커스 두고 Enter / Space | **hue 는 그대로, 커스텀만 선택** | mono → Enter → `custom` (hue 40 유지) · ember → Space → `custom` |
| 카드 여백 클릭 | 기존대로 커스텀 선택 | 변경 없음 |

**접근성 — 카드를 `role="button"` 에서 뺐다.** ARIA 규격상 `role=button` 의 자손은
presentational children 이라 **슬라이더가 보조기술 트리에서 통째로 사라진다.** 그래서
커스텀 카드만 `role="group"` + `aria-labelledby` 로 바꾸고, 포커스는 슬라이더가 직접 받는다
(`aria-label` = g960, 3언어). 나머지 `.toggle-card` 는 `role=button`/`tabindex=0` 그대로다.

## B-3. 배경 투명 시 미리보기 위 배치 버튼

`#stage` 위 오버레이 한 줄의 오른쪽에 `#stageBackdropPick` (인라인 SVG «사진» 아이콘 + 라벨).
배경이 **투명일 때만** 뜬다 — 불투명 배경에서는 표면이 안 보여 배치 미리보기가 의미를 잃는다
(패널 섹션의 노출 조건과 같은 `on` 을 쓴다).

**중복 상태 동기화**: 노출·라벨·title 을 `syncBackdropUi()` **한 함수 안에서** 패널 버튼과
나란히 갱신하고, 클릭도 같은 `els.backdropFile.click()` 한 줄을 부른다. 실측 — 사진을 넣은 뒤
두 버튼 라벨이 문자열 단위로 일치 (`이미지 교체… (surface-test.png)`, `synced: true`).

앵커는 캔버스 상자가 아니라 **무대의 패딩 박스**(top/right 14px)다. 상자에 붙이면 코드
종횡비에 따라 버튼이 좌우로 널뛰고, 세로로 긴 코드에서는 같은 줄에 안내 문구가 들어갈 자리가
없다. 오버레이 컨테이너는 `pointer-events: none` 이고 버튼만 `auto` — 배경 드래그를 막지 않는다.
긴 파일명은 **span 쪽 말줄임**으로 자른다 (flex 컨테이너의 `text-overflow` 는 넘치는 flex
아이템에 적용되지 않아, 처음엔 말줄임 없이 잘렸다 — 375px 실측에서 잡았다).

## B-4. 배경 삽입 시 조작 안내 오버레이

같은 줄 왼쪽에 `#backdropGestureHint` — 13px/600 굵기의 반투명 알약 (폰 12px), 아이콘은
사방 화살표 인라인 SVG. 문구 g962:

| 언어 | 문구 |
|---|---|
| ko | 드래그로 위치 이동 · 휠 또는 핀치로 확대/축소 |
| en | Drag to move · scroll or pinch to zoom |
| ja | ドラッグで移動・ホイールまたはピンチで拡大縮小 |

### 사라지는 방식 — 왜 이렇게 정했나

이 안내가 가리는 것은 **지금 판단하려는 그 표면 사진**이다. 계속 띄워 두면 배치 미리보기의
목적 자체를 방해한다. 그래서 «필요한 순간에만»:

1. **첫 조작(pointerdown · wheel)에서 페이드아웃** (0.45s). 안내가 전달됐다는 게 증명된 시점이다.
2. **아무 조작이 없어도 7s 뒤 페이드아웃.** 조작할 생각이 없는 사용자에게 영구 가림막이 되지
   않게. (세 언어 한 줄을 읽는 데 필요한 시간보다 넉넉하다.)
3. **새 사진을 넣거나 «위치 초기화» 를 누르면 다시 뜬다** — 배치를 처음부터 다시 하는
   순간이라 같은 안내가 다시 유효하다.
4. 사라지는 건 안내뿐이고 **같은 내용이 패널 힌트(g300)와 «?»(g903)에 상시로 남아 있다.**

구현 세부 둘:

* **에지 검출.** `syncBackdropUi()` 는 렌더·드래그 종료·휠 정지마다 돈다. 거기서 무조건
  띄우면 **조작을 멈출 때마다 되살아나** 페이드가 무의미해진다. «안 보임 → 보임» 으로 넘어간
  순간에만 띄운다 (`backdropWasShowing`).
* **rAF 대신 강제 리플로.** 처음엔 `requestAnimationFrame` 으로 `.faded` 제거를 미뤘는데,
  실브라우저에서 **탭이 백그라운드면 프레임이 안 돌아 콜백이 밀렸다** — 그 사이 7s 타이머가
  먼저 지나면 «숨긴 뒤에 다시 보이는» 순서 역전이 난다. `void el.offsetWidth` 로 바꿨다.
  (라이브에서 `faded:true / opacity:0` 로 잡아서 고친 실제 결함이다.)
* `prefers-reduced-motion: reduce` 에서는 전이를 0.01s 로 줄인다.

### «핀치» 를 말하려면 핀치가 있어야 한다 — 두 손가락 줌을 실제로 구현했다

기존 코드에는 **휠밖에 없었다.** 터치 기기에는 휠 이벤트가 없으므로 폰에서는 확대/축소 경로가
아예 없었고, 안내에 «핀치» 를 쓰면 그 문구가 거짓이 된다. 그래서 UI 층에서 두 손가락을 처리한다
(인코딩·게이트 무관):

* 눌린 포인터를 `Map` 으로 추적. 1개 = 팬(기존), 2개 = 핀치.
* 핀치는 **중점 이동 = 팬**, **거리 비 = 줌**을 같은 프레임에 적용하고, 줌 앵커는 두 손가락의
  중점. 휠과 **같은 `zoomAt()`** 을 쓴다 (한쪽만 고쳐지는 것을 막는다). 배율 클램프 0.05\~20 유지.
* 두 손가락 중 하나만 떼면 남은 손가락으로 팬을 이어받는다.
* `#canvasWrap { touch-action: none }` 은 이미 있어 브라우저 기본 제스처와 다투지 않는다.

**실측 (합성 PointerEvent · 흰 배경에 빨간 사각을 넣고 backdrop 캔버스의 빨강 런 길이를 잼)**

| 조작 | 빨강 폭 (캔버스 px) | 배율 |
|---|---|---|
| 기준 (cover fit) | 318 | 1.00 |
| 두 손가락 간격 100 → 200 | **636** | **2.00** |
| 다시 200 → 100 | **318** | **1.00** (원위치 복귀) |

문구가 «휠만» 이라고 말하던 기존 키도 **세 언어 모두** 핀치를 포함하도록 고쳤다 —
`g207` · `g300`(패널 힌트) · `g903`(«?» 본문) + 정적 DOM 기본 문구. 테스트가 네 키 전부에서
각 언어의 «핀치/pinch/ピンチ» 를 요구한다.

## C-2. ESC 를 어떻게 고쳤나 (`src/help-popover.js`)

원인은 «닫은 뒤 무조건 `focusTarget.focus()`» 였다. 클릭-고정 경로는 버튼에 이미 포커스가
있어 `focus()` 가 no-op → 통과했고, **hover 경로만** focus 이벤트가 실제로 발화해
`focus` 리스너가 방금 닫은 창을 다시 열었다. 소스를 읽으면 «close() 를 부르니 닫힌다» 로
보이는 종류의 결함이다 — 두 경로를 **각각 굴려야** 보인다.

```js
const restore = focusIsInside(focusTarget);   // 앵커 or 팝오버 안에 포커스가 있을 때만
close();
if (restore) focusWithoutReopen(focusTarget); // 그 호출도 억제 플래그로 감싼다
```

같이 넣은 것: 고정 시 `closeButton` 으로 포커스 이동(X 키보드 도달성) · X 클릭과 토글
닫기에서도 앵커로 포커스 복귀. `role="tooltip"` 은 그대로 뒀다 — 역할 교체는 별도 판단거리다.

**뮤테이션 확인**: 옛 ESC 동작 복원 / 억제 플래그 제거 / 포커스 이동 제거 3개를 심으니
각각 정확히 대응하는 테스트가 실패했다 (16개 중 3개). 새 테스트가 하중을 받는다.

## D-2. 3-way 가 **떨군** 파일 6개

`git apply -3` 에 실린 패치는 **추적 중인 파일의 diff** 였다. gen-ui 워크트리에서 아직
`git add` 되지 않은 신규 파일은 패치에 애초에 없었고, 그래서 충돌도 안 나고 **조용히
사라졌다** — 마커 0 · 스위트 초록으로 «통합 완료» 로 보이는 상태였다.

```
src/help-popover.js                  ← MODULE_ORDER 가 이름만 알고 실체가 없었다
test/generator-help-capacity.test.js ← 용량 수치 핀 (§4 정정의 재발 방지 장치 자체)
test/generator-help-ui.test.js       ← A-1~A-7 계약 20건
test/generator-preview-ui.test.js    ← 과업 B 계약 19건
test/help-popover-behavior.test.js   ← 과업 C (ESC·포커스)
test/self-check-verdict.test.js      ← 3태 판정 단위 7건
```

**«마커 0 = 통합 완료» 가 아니다.** 충돌 마커는 두 쪽이 *같은 줄*을 만졌을 때만 생긴다.
한쪽에만 있는 파일은 마커를 만들 수 없고, 그 파일이 하필 **검증 장치**면 손실이 두 배다 —
없어진 테스트는 자기가 없어졌다고 말하지 않는다. 대조는 파일 목록으로 해야 한다
(`diff <(git ls-files) <(git ls-files)` + 양쪽 `git status` 의 `??` 줄).

## D-3. 의미 합성 — 3-way 가 넘긴 결함 3

### ① v0XQ 카드가 «이름만» 남아 있었다

병합 결과의 v0XQ 카드는 이랬다:

```html
<div class="toggle-card" data-locator="cell-surface-v0xq">
  <span data-i18n="g604">셀 표면 v0XQ · 중앙 QR (Y1)</span>
</div>
```

형제 6장은 전부 **아이콘 + 부제**를 갖는데 이 한 장만 없다. gen-ui 는 v0XQ 를 몰랐고,
main 은 gen-ui 관용구를 몰랐다 — 어느 쪽도 «빠졌다» 고 말할 수 없는 자리다.

붙인 것: 파인더 기하 미니 SVG(**겹사각 3코너 + 중앙 파선 슬롯**) + 부제 `g947`
«3코너 + 중앙 QR» 3언어. 아이콘 규약을 하나 넓혔다 — **파선 사각 = 중앙 QR 슬롯**.
슬롯은 파인더도 데이터도 아닌 제3 역할이라 실선 블록과 같은 획으로 그리면 «파인더가
123셀» 로 읽힌다.

**테스트도 상수를 빼고 다시 짰다.** 원래는 `svg` 개수를 `6` 으로 박고 부제 키 6개를
나열했다. 그 모양이면 카드가 늘 때 «6 을 7 로 고쳤다» 로 끝나고, 이번처럼 **아이콘 없는
카드가 들어와도 초록**이다. 지금은 카드 수를 세어 아이콘 수·부제 키 수와 **서로 맞춘다**.

### ② lab 게이트 테스트가 «게이트» 가 아니라 «문자열» 을 세고 있었다

```js
// 옛 판
const gates = INDEX.match(/const show = isLabPath\(\) && generatorState\.type === 'Y';/g);
assert.equal(gates.length, LAB_ONLY_SECTIONS.length);   // 1 !== 2 로 실패
```

이 한 줄에는 두 가지가 섞여 있다 — ⓐ **lab 게이트**(`isLabPath`)와 ⓑ **어떤 타입에서
열리는가**. main 의 셀 편집기가 Y/O/A 로 넓어지며 ⓑ 가
`CELL_EDITOR_TYPES.includes(generatorState.type)` 로 바뀌자 개수가 2→1 이 됐다.
**ⓐ 는 멀쩡한데 테스트가 깨진다** — 즉 옛 판은 자기가 지킨다고 적은 것(lab 노출 차단)이
아니라 우연히 같이 있던 타입 조건을 지키고 있었다.

지금은 게이트를 **섹션에 묶어서** 잰다: `LAB_ONLY_SECTIONS` 각각에 대해 자기 sync 함수
안에서 `const show = isLabPath() && …` → `section.hidden = !show;` 가 이어지는지 본다.
타입 조건은 각 섹션 소관이라 여기서 안 박는다. 약화가 아니라 **묶음 강화**다 — 옛 판은
게이트가 어느 섹션 것인지 몰랐고, 지금은 안다.

### ③ g906 용량표에 v0XQ 행이 없었다

이 문서 §4 정정이 만든 «문구 ↔ 정본 대조» 장치는 **표에 적힌 행만** 검사한다. 없는 행은
검사도 안 되므로, v0XQ 카드가 화면에 있는데 도움말에는 없는 상태가 초록으로 통과한다.

| v0XQ @ n=21 | **42** | **81** | 288 | 96 | **80 / 67 / 54** |

**이 행이 §4 의 논증을 하나 뒤집는다.** 원문은 «점유 셀이 적을수록 용량이 크다,
단조다» 였다. v0XQ 는 파인더가 42 로 **가장 작은데** 용량은 넷 중 **가장 작다** —
슬롯 81셀이 데이터에서 빠지기 때문이다. 그래서 세 언어 문구를 이렇게 고쳤다:
